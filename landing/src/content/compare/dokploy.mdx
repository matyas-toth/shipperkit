Dokploy and Shipper look alike at first: both put Traefik in front of Docker and give you a dashboard for apps, databases and domains. They differ in where they are headed. Dokploy grows toward clusters, teams and a commercial cloud. Shipper stays focused on one server and on making releases, backups and restores hard to get wrong.

## Choose ShipperKit if

- **You want everything under one permissive license.** Shipper is MIT licensed with no proprietary directories, paid plans or enterprise keys. Roles, sign-in providers and two-factor authentication are in the free release.
- **Your server is small.** Shipper installs on 1 GiB of RAM, on x86-64 or ARM64.
- **Releases have to fail safely.** A failed build or health check never takes traffic, and a rollback restores the exact image and settings that ran before.
- **You want restores you can't get wrong.** Database and volume restores always create a copy, and the instance itself can be recovered from an encrypted archive.
- **Your coding agent deploys for you** with a token limited to one application and the actions it needs.

## Choose Dokploy if

- **You need several servers or Docker Swarm** for replicas and placement.
- **You rely on pull request previews**, buildpacks or Nixpacks.
- **You want a hosted option**, an MCP server, an SDK or many notification channels.
- **Your organization needs SAML or custom roles**, and an enterprise license is fine.

## Moving from Dokploy

Applications built from a Dockerfile, Compose file or image move as they are. Install Shipper on a fresh server, deploy each app from the same source, restore database dumps as new databases, and switch DNS when each one checks out. The [move an existing app](/docs/move-an-app/) guide walks through the order.
