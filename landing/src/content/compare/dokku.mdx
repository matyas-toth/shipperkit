Dokku is the original "your own Heroku on one server", and it's still excellent if you live in a terminal. Shipper shares its scope of one server and its MIT license, but it's built around a dashboard, so a teammate who has never opened an SSH session can still deploy, read logs and restore a backup.

## Choose ShipperKit if

- **You want a dashboard without paying for one.** Every screen in Shipper is part of the MIT release, including roles, sign-in providers and two-factor authentication.
- **You want databases, HTTPS and backups without assembling plugins.** They're part of Shipper itself and share one model and one place in the dashboard.
- **Your team doesn't all use SSH.** People sign in with email, Google, GitHub or Discord and get the role you give them.
- **You deploy Compose stacks or ready-made services.** Shipper builds Compose files from source and has 365 one-click services.
- **Your coding agent deploys for you** with a token scoped to one application, instead of an SSH key.

## Choose Dokku if

- **You want git push to be the whole interface**, and a CLI is all you need.
- **You rely on Heroku buildpacks** or a Procfile workflow you already have.
- **You want to pick your proxy**, since Dokku supports nginx, Caddy, HAProxy, OpenResty and Traefik.
- **You value a very long track record** and a large plugin ecosystem.

## Moving from Dokku

Apps with a Dockerfile move as they are, and many buildpack apps build with Railpack without changes. Install Shipper on a fresh server, deploy from the same repository, restore your database dumps as new databases, and switch DNS when each app checks out. The [move an existing app](/docs/move-an-app/) guide walks through the order.
