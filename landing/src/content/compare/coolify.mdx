Coolify is the best-known self-hosted PaaS, and for good reason. It covers more ground than Shipper does today: many servers, pull request previews, more Git providers and more notification channels. Shipper is deliberately smaller. It runs one server well, asks for fewer decisions along the way, and puts most of its effort into what happens when a deploy or a disk goes wrong.

## Choose ShipperKit if

- **You run one server and want it to stay light.** Shipper is a single Go service with SQLite and Traefik, and it installs on a 1 GiB machine. Coolify asks for 2 GB of RAM and runs its own PostgreSQL and Redis.
- **You want fewer concepts.** In Shipper the application is the main object. You don't create a project, an environment and a destination before your first deploy.
- **Releases have to fail safely.** A failed build or health check never takes traffic, and every release records the image and settings that actually ran, so a rollback restores exactly that instead of rebuilding a branch.
- **You want restores you can't get wrong.** Database and volume restores always create a copy, and instance archives are encrypted with a recovery key you keep off the server.
- **Your coding agent deploys for you.** Tokens can be limited to one application and a few capabilities, and every CLI command has a `--json` form.

## Choose Coolify if

- **You manage several servers** from one dashboard, or need separate build servers.
- **You rely on pull request previews**, GitLab or other Git providers, or existing Nixpacks configurations.
- **You want an MCP server**, more notification channels such as Slack and Telegram, or a hosted control plane through Coolify Cloud.
- **You need KeyDB or Dragonfly** as managed databases.

## About the Service Library

Shipper's Service Library is generated from Coolify's open source service templates under the Apache 2.0 license, and we credit them in our [third-party notices](https://github.com/matyas-toth/shipperkit/blob/master/THIRD_PARTY_NOTICES.md). Each template is converted to Shipper's application model, with its secrets generated on deploy.

## Moving from Coolify

Your applications are Docker images, Dockerfiles or Compose files, so they move without rewrites. Install Shipper on a fresh server, deploy each app from the same repository, restore your database dumps as new databases, and switch DNS when each one checks out. The [move an existing app](/docs/move-an-app/) guide walks through the order.
